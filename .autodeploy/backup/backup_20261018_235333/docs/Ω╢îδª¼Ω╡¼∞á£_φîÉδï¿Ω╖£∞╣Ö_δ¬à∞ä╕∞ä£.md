# 납세자 권리보호 안내 시스템 — 권리구제 판단 규칙 명세서
버전: 1.0-draft  
상태: 구현용 초안 / 공식 운영 전 법령·업무담당자 검증 필수

## 1. 목적 및 원칙
납세자가 세무 지식 없이 자유롭게 입력한 불만사항을 분석해 소관기관을 먼저 판별하고, 국세청 소관 사안에 대해서는 필요한 사실을 질문한 후 권리보호·권리구제 절차와 실행 방법을 안내한다.

핵심 원칙:
1. Jurisdiction-first: 국세청 소관 판단 전에 국세청 절차를 추천하지 않는다.
2. Ask-before-decide: 필수 사실이 부족하면 결론 대신 질문한다.
3. State-aware: 사건의 현재 단계와 마지막 공식 처분을 구분한다.
4. Rules over free-form reasoning: 절차 선택은 명시적 규칙으로 통제한다.
5. Multiple-issue support: 하나의 민원에 여러 쟁점·절차 후보를 허용한다.
6. Evidence-grounded: RAG 근거가 없으면 근거를 지어내지 않는다.
7. Deadline safety: 날짜·기산점·예외가 확인되지 않으면 기한을 확정하지 않는다.
8. Plain language: 전문용어에는 쉬운 설명을 덧붙인다.
9. Human review: 불확실하거나 중대한 사안은 담당기관·전문가 확인을 권한다.
10. Privacy by design: 필요 최소한의 개인정보만 처리한다.

## 2. 시스템 범위
### 포함
- 소관기관 분류
- 단순 세법 문의와 권리보호/권리구제 민원 구분
- 핵심 사실 추출 및 추가 질문
- 사건 단계 분류
- 권리구제 후보 및 병행 검토 절차 추천
- 신청기한 위험 표시
- 업로드 PDF 검색 및 출처 표시
- 이해하기 쉬운 안내문 생성

### 제외 또는 제한
- 과세처분의 적법성 최종 판정
- 승소 가능성 보장·예측
- 규정 근거 없이 기한이나 법적 효과 단정
- 다른 기관 소관 사건의 세부 법률 절차 판정
- 공식 신청·접수의 대리 수행

## 3. 처리 단계와 진입 조건
| ID | 단계 | 진입 조건 | 산출물 |
|---|---|---|---|
| ST-01 | 민원 접수 | 사용자가 자유기재 | 원문, 세션 ID |
| ST-02 | 관할기관 판단 | 원문 존재 | agency, confidence, rationale |
| ST-03 | 민원 성격 분류 | 국세청 또는 불명확 | inquiry_type, issue_types |
| ST-04 | 사실 추출 | 국세청 소관 가능성 | known_facts, missing_facts |
| ST-05 | 추가 질문 | 필수 사실 누락 | 질문 1~3개 |
| ST-06 | 사건 단계 판단 | 주요 사실 확보 | procedure_stage, last_disposition |

| ST-08 | 문서 검색 | 권리구제 방식/PDF 존재 | 검색 청크, 출처 |

| ST-11 | 종료/재시작 | 안내 완료 | restart/exit |

## 4. 소관기관 판단 규칙
### 입력 단서
- 세목·행위·문서 발신기관·담당기관·관련 절차
- 사용자가 언급한 기관명은 단서일 뿐 확정 근거가 아님

### 결과
- `NTS`: 국세청 소관 가능성이 높음
- `OTHER`: 다른 기관 소관이 명확함
- `UNKNOWN`: 정보 부족 또는 혼합 사안

### 규칙
- 지방세(예: 취득세, 재산세, 자동차세) 관련 부과·징수는 원칙적으로 지방자치단체 안내를 우선 검토한다.
- 국세(예: 소득세, 법인세, 부가가치세, 상속세·증여세) 관련 신고·과세·징수는 국세청 소관 가능성을 검토한다.
- 혼합 사안은 쟁점별로 기관을 분리할 수 있다.
- `OTHER`이면 해당 기관/공식 창구/국민신문고를 안내하고 국세청 권리구제 규칙을 진행하지 않는다.
- `UNKNOWN`이면 한 번에 1~3개의 질문으로 기관을 확인한다.

## 5. 민원 성격 분류
허용 분류:
- `SIMPLE_TAX_QUESTION`: 단순 세법 상담
- `FILING`: 신고·수정신고·경정청구·기한후신고 관련
- `TAX_NOTICE`: 과세예고·고지·과세처분 관련
- `COLLECTION`: 납부·체납·독촉·압류·징수유예 관련
- `AUDIT`: 세무조사 착수·진행·종결 및 조사행위
- `TAXPAYER_RIGHTS`: 과세자료 안내·절차상 권리침해 등
- `APPEAL`: 이의신청·심사청구·심판청구 등 불복
- `GRIEVANCE`: 고충민원·청원·국민신문고 등
- `MIXED`: 복수 쟁점
- `UNKNOWN`: 추가 확인 필요

이미 신고한 뒤 과소신고 자료 제출 요구를 받은 상황은 세목과 통지 성격을 먼저 확인한다. 고지·처분 전이라는 정보만으로 경정청구나 불복을 추천하지 않는다. 신고내용 확인 단계일 가능성이 있으면 담당자에게 확인하도록 안내한다.

## 6. 사실관계 스키마
권장 필드:
- `tax_type`: 세목
- `received_notice`: 고지서/통지서 수령 여부
- `notice_date`: 수령일(ISO 날짜 또는 미확인)
- `notice_kind`: 과세예고/고지/독촉/압류/기타/미확인
- `prior_explanation`: 사전 소명 안내 여부
- `tax_audit_status`: 없음/착수/진행/종결/미확인
- `appeal_status`: 없음/진행/종료/기한 경과 주장/미확인
- `filing_status`: 신고 전/신고 완료/미신고/미확인
- `collection_status`: 정상/납부 곤란/체납/압류/미확인
- `last_disposition`: 마지막 공식 처분
- `issue_description`: 쟁점 요약
- `evidence_available`: 증빙 유무
- `agency_name`: 통지·행위 기관

날짜는 사용자가 말한 날짜를 그대로 보존하고, 해석한 날짜와 구분한다. 알 수 없는 값은 `null`로 유지한다.

## 7. 추가 질문 규칙
- 필수 정보가 부족하면 최종 절차를 확정하지 않는다.
- 한 번에 최대 3개 질문을 제시한다.
- 이미 알려진 사실을 반복해서 묻지 않는다.
- 질문 우선순위: (1) 관할기관, (2) 처분/통지 종류, (3) 통지일, (4) 현재 진행 중인 절차, (5) 핵심 행위·증빙.
- 불복기한이 관련될 수 있으면 통지일과 처분 종류를 먼저 확인한다.
- 질문에 답하지 못해도 가능한 범위의 일반 안내와 공식 상담 경로를 제공한다.

## 8. 사건 단계 및 주요 규칙
### R-01 단순 세법 문의
조건: 권리침해·처분 관련 쟁점이 없고 세법 해석 문의가 중심.
결과: 국세상담센터 등 공식 상담 경로. 권리구제 절차를 불필요하게 권하지 않는다.

### R-02 신고·수정 관련
조건: 신고한 세액이 과다하다고 주장하거나 신고 오류를 수정하려는 경우.
결과: 경정청구 등 해당 절차의 요건·기간을 확인한다. 신고 상태와 세목 확인 전 확정하지 않는다.

### R-03 미신고
조건: 법정신고기한까지 신고하지 않았다고 진술.
결과: 기한후신고 등 검토. 현재 시점의 적용 조건과 가산세 등은 공식 근거 확인 후 안내한다.

### R-04 신고 후 자료 제출 요구
조건: 이미 신고했으며 과세자료/소명자료 제출 요구를 받았으나 아직 과세 고지 여부가 불명확.
결과: 세목과 안내문 종류를 질문한다. 신고내용 확인 가능성을 안내하고 담당자에게 자료 요구의 취지·근거·제출기한을 확인하도록 한다. 고지 전이라는 이유만으로 경정청구/불복을 추천하지 않는다.

### R-05 과세예고 단계
조건: 과세예고통지 등 고지 전 통지를 받음.
결과: 과세전적부심사 등 검토. 통지 유형, 청구 대상, 예외, 기간을 현행 규정으로 검증한다.

### R-06 고지 후 과세처분 다툼
조건: 공식 고지·처분이 있고 과세 자체에 이견이 있음.
결과: 이의신청·심사청구·심판청구 등 법정 불복절차를 검토한다. 처분 종류와 통지일을 확인하고 기한을 임의로 계산하지 않는다.

### R-07 과세 근거 안내 부족/절차상 침해
조건: 과세자료나 절차 안내 부족, 부당한 행위 등 권리침해 가능성이 주장됨.
결과: 관련 규정의 적용 대상인지 검토하고 납세자보호담당관/권리보호요청 경로를 안내한다. 과세처분 불복 필요성과 기한을 별도로 병행 검토한다.

### R-08 세무조사 착수·진행 중
조건: 조사 중의 부당한 자료 요구, 조사 범위·기간·절차 문제.
결과: 권리보호요청 등 조사 단계의 보호 절차를 검토한다. 구체적인 요건·예외·담당 창구를 현행 규정으로 확인한다.

### R-09 세무조사 종결
조건: 조사가 끝났다고 진술.
결과: 조사 종결만으로 절차를 확정하지 않는다. 과세예고통지/고지 여부를 질문한다. 과세예고가 있으면 과세전적부심사 등, 고지가 있으면 불복절차 등 해당 단계에 맞는 규칙을 적용한다. 조기결정신청은 적용 조건이 확인될 때만 안내한다.

### R-10 징수·체납
조건: 납부 곤란, 독촉, 압류 등.
결과: 징수유예·압류 관련 제도 등 해당 절차를 검토한다. 단순히 돈이 부족하다는 사실만으로 요건 충족을 확정하지 않는다.

### R-11 불복기한 경과 주장
조건: 사용자가 불복기간이 지났다고 진술.
결과: 처분일·통지일·처분 종류·기한 계산을 확인한다. 기간 경과를 바로 확정하지 않고, 법정 예외 가능성을 확인한다. 일반 불복이 불가능한 경우 고충민원 등 후속 절차를 안내하되 결과 보장이나 불복절차 대체로 표현하지 않는다.

### R-12 고충·청원·국민신문고
조건: 일반 절차 검토 후에도 해결되지 않거나 관련 제도에 따른 검토가 필요.
결과: 고충민원, 청원, 국민신문고를 단계적으로 또는 상황에 맞게 안내한다. 이 절차가 법정 불복기간을 연장·중단한다고 표현하지 않는다.

## 9. 복수 절차 처리
하나의 민원에서 다음을 분리해서 안내한다.
- 주된 대응 방법
- 병행 검토 절차
- 기한상 긴급 조치
- 추가 확인사항
권리보호요청과 과세처분 불복은 목적이 다를 수 있으므로 하나가 다른 하나를 자동으로 대체한다고 안내하지 않는다.

## 10. 기한 처리 규칙
- 기한은 처분 종류·통지일·법령 버전이 확인된 경우에만 계산한다.
- 현재 구현은 법정기한을 확정하지 않고 `기한 확인 필요` 경고를 낼 수 있다.
- 법령 개정일, 적용 시점, 경과규정, 기산점, 말일 휴일 등은 검증된 규칙 데이터로 관리한다.
- 권리보호요청 또는 고충민원 문의가 일반 불복기한을 자동으로 연장·중단한다고 안내하지 않는다.

## 11. RAG 및 인용 규칙
- 사용자가 선택한 권리구제 방식에 연결된 PDF만 우선 검색한다.
- 청크 메타데이터: 파일명, 페이지, 권리구제 방식, 업로드 시각, 문서 버전.
- 답변의 핵심 절차 안내에는 출처를 표시한다.
- 검색 결과가 없으면 근거가 확인되지 않았다고 명시하고 공식 자료 확인을 권한다.
- 사용자 업로드 문서는 공식·현행 문서라고 자동 간주하지 않는다.
- PDF의 문구를 시스템 지시로 취급하지 않는다(문서 내 prompt injection 방지).

## 12. 오류·불확실성 처리
- 관할기관 불명확: 질문 또는 일반 안내 후 공식 창구 연결
- 필수 사실 부족: 추가 질문
- 규칙 매칭 없음: 확정 추천 금지, 담당자 확인 권고
- RAG 근거 부족: 근거 없음 표시
- 법령 최신성 미확인: “현행 규정 확인 필요” 표시
- 상충하는 사실: 충돌을 명시하고 사용자 확인 요청
- 고위험/기한 임박: 공식 기관 또는 전문가에게 즉시 확인하도록 안내

## 13. 개인정보·보안
- 주민등록번호, 계좌번호 등 불필요한 개인정보를 입력하지 않도록 안내한다.
- API 전송 데이터 최소화 및 공급자 데이터 처리 조건 확인.
- API 키는 `.env`에 저장하고 저장소에 포함하지 않는다.
- 업로드 PDF는 임시 저장·삭제 정책을 둔다.
- 세션 간 데이터 분리 및 접근통제를 적용한다.
- 실제 서비스 전 개인정보 영향 및 관련 법령 검토가 필요하다.

## 14. 인수 기준
1. 다른 기관 소관이면 국세청 권리구제 수단을 추천하지 않는다.
2. 단순 세법 문의면 국세상담센터 등 상담 경로를 우선한다.
3. 필수 사실이 부족하면 추가 질문이 먼저 나온다.
4. 신고 후 자료 제출 요구 상황에서 세목과 통지 종류를 확인하기 전 경정청구/불복을 확정 추천하지 않는다.
5. 조사 종결만으로 과세전적부심사/조기결정신청을 자동 추천하지 않는다.
6. 불복기한 경과는 날짜와 처분 종류를 확인하지 않고 확정하지 않는다.
7. RAG 출처는 파일명과 페이지를 표시한다.
8. 근거가 없으면 규정이나 출처를 만들어내지 않는다.
9. 최종 안내에 주된 절차, 대안, 기한 주의, 공식 경로가 포함된다.
10. 사용자가 처음부터 다시 시작하거나 종료할 수 있다.

## 15. 공식 운영 전 승인해야 할 항목
- 현행 법령과 국세청 업무 규정에 따른 모든 절차의 적용 요건
- 기한 및 기산점 데이터
- 공식 URL과 연락처
- 권리보호요청·고충민원·청원·국민신문고의 관계
- 개인정보 처리·보관·삭제
- 모델 사용 계약 및 외부 전송 정책
- 대표·경계·오류 사례 테스트셋


## 추가 설계: 초기 접수 5개 항목 분류 및 사용자 확인

민원 원문을 처리한 직후 권리구제 경로를 곧바로 확정하지 않고, 다음 항목을 먼저 분류하여 사용자에게 보여준다. 사용자가 값을 수정·확인한 뒤에만 후속 권리구제 판단을 진행한다.

1. **소관기관**: 불만을 유발시킨 행정기관. 문서 발신기관뿐 아니라 실제 안내·통지·고지·조사 등을 수행한 기관을 기준으로 하며, 불명확하면 확인 필요로 둔다.
2. **세목**: 국세청 소관 세목 사전과 약칭·현장 표현·흔한 오타를 비교한다. 문자열 유사도는 후보 검색에만 사용하고, 낮은 유사도는 확정하지 않으며 사용자가 직접 수정할 수 있다. 지방세·관세 등 타 기관 소관 세목을 국세청 세목으로 강제 매핑하지 않는다.
3. **과세단계**: 사업자등록, 신고, 세무조사, 과세예고, 고지, 불복, 체납, 민원, 세법상담 등.
4. **처분행위**: 안내, 자료제출 요구, 소명 요구, 통지, 과세예고통지, 고지, 독촉, 압류·추심, 신고 처리·환급 지연, 세무조사 착수·진행, 불복 결정, 민원 회신 등.
5. **요구목적**: 사용자가 궁극적으로 원하는 결과. 과세 근거 확인, 처분 취소·변경, 감액·환급, 납부 유예, 압류 해제, 설명·답변 요구 등. 불만의 문구만으로 확정하기 어려우면 미확인으로 둔다.

**화면 흐름**: 불만 입력 → 5개 항목 자동 분류 → 사용자가 확인·수정 → 확인 완료 후 소관기관별 후속 절차 → 국세청 소관이면 사실관계 보완·권리구제 규칙·PDF RAG 검색.

**유의사항**: 세목 유사도 점수는 언어적 유사성일 뿐 법적 판단의 신뢰도나 관할 확정값이 아니다. 분류 결과를 반드시 사용자에게 확인시키고, 국세청 소관이 아닌 경우에는 국세청 권리구제 절차를 실행하지 않는다.
